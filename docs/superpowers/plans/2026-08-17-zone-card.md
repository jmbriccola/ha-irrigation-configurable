# Zone Card Implementation Plan

> **Execution note:** this plan is executed **inline, by the author of the spec**, not dispatched to fresh subagents. It is therefore a work breakdown with exact interfaces, file boundaries and test lists — not a self-contained brief that restates every line of TypeScript twice. Code appears where the design is subtle or easy to get wrong; elsewhere the spec section is cited and the interface is pinned. Anyone picking this up cold should read the spec first.

**Goal:** `irrigation-maestro-zone-card` — the detailed per-zone card, with a visual editor and eight individually toggleable blocks.

**Architecture:** New Lit elements in the existing bundle, composed by a shell; pure tested modules for the calendar phrasing and the history fetch; a hand-drawn SVG chart. Reuses `discovery.ts`, `schedule-math.ts`, `curve-editor.ts`, `format.ts` and `flow-units.ts` rather than reimplementing them.

**Spec:** [`docs/superpowers/specs/2026-08-17-zone-card-design.md`](../specs/2026-08-17-zone-card-design.md)

## Global Constraints

- **Engine untouched:** `weather.py`, `curves.py`, `evaluate.py`, `history.py`, `planner.py` byte-identical. Hashes in `/tmp/engine-hashes-b3.txt`.
- **`zone-row.ts` and `card.ts` are not refactored.** They belong to the live `irrigation-maestro-card`, which branch 5 owns. Reuse the pure modules; write new rendering.
- **No literal colours** in any new component's styles. Every fill/stroke is an HA CSS custom property with a fallback. Meaning is carried in *shape* (hatch, marker), never in hue alone.
- **No new runtime dependency.** `card/package.json` dependencies stay `lit` only.
- **Both dictionaries, same order.** `TranslationKey = keyof typeof en`; `it` is typed `Record<TranslationKey, string>`, so a missing key fails `npm run typecheck`. `localize.test.ts` asserts parity *and* insertion order — add keys to both files at the same position.
- **Italian is fixed vocabulary:** *flussometro*, *sensore di perdita*, *sensore di mancanza d'acqua*, *acqua non attribuita*, *litri stimati*, *secondi non osservati*, *storico dei consumi*. Weekday/month names come from the dictionary, never `toLocaleDateString`.
- **Same bundle, same resource.** The new type is registered in `card/src/index.ts`; `resources.py` and `const.py` are untouched.
- Commands: `.venv/bin/pytest` (bare); in `card/`: `npm run test`, `npm run typecheck`, `npm run build`.
- Baseline: **841 Python tests** on `main` at 3.6.0; card suite green.

**Files:** `custom_components/irrigation_maestro/sensor.py` (`_cycle_dict`), `tests/components/test_entities.py`, `docs/design/card-contract.md`

- [ ] Test first, in `test_entities.py`: a zone's `zone_state.cycles[0]["last_completed"]` is `None` before any completion, and equals the marker's ISO date after `runtime.state.set_last_completed(zone_id, cycle_id, date(...))`. Run it, see it fail on `KeyError`.
- [ ] In `_cycle_dict`, add:
  ```python
              "last_completed": (
                  marker.isoformat()
                  if (marker := self._runtime.state.last_completed(self._zone_id, cycle.cycle_id))
                  else None
              ),
  ```
- [ ] `card-contract.md`: add `last_completed` to the `cycles` JSON example and one line — ISO date or `null`, the marker that gates INTERVAL mode only, per zone **and** program.
- [ ] Green, `ruff`/`mypy`, full Python suite, commit.

### Task 2: `calendar-text.ts` — the calendar in words

**Files:** `card/src/calendar-text.ts`, `card/src/calendar-text.test.ts`, `card/src/localize/{en,it}.ts`

Spec §3.2. Pure module, no Lit, no `Date` formatting beyond what the dictionary gives.

**Interface:**
```ts
export interface CalendarConfig {
  mode: "weekdays" | "interval" | "parity";
  days?: number[];
  interval_days?: number;
  parity?: "odd" | "even";
}
export function calendarText(
  lang: string,
  calendar: CalendarConfig | undefined,
  lastCompleted?: string | null,
): string;
```

- [ ] Write `calendar-text.test.ts` first, covering every row of spec §3.2's table plus: an empty `days` array, all seven days, an unknown mode (returns the "every day" fallback rather than throwing — a card must not blank because storage grew a mode), `interval_days: 1`, and both languages.
- [ ] Run, see it fail.
- [ ] Add dictionary keys to **both** files at the same position: weekday short names (7), `calendar.every_day`, `calendar.weekdays` (`{days}`), `calendar.interval` (`{n}`), `calendar.interval_one`, `calendar.parity_odd`, `calendar.parity_even`, `calendar.last_completed` (`{date}`), `calendar.never_completed`.
- [ ] Implement. Join weekdays with the locale's list conjunction from the dictionary (`list.and`), not a hardcoded ", " — Italian wants "lun e gio".
- [ ] `npm run test`, `npm run typecheck`, commit.

### Task 3: `water-history.ts` — fetch, cache, normalize

**Files:** `card/src/water-history.ts`, `card/src/water-history.test.ts`

Spec §4.3. The one rule that matters: **never fetch on render**.

**Interface:**
```ts
export interface HistoryDay { date: string; l: number; est: boolean; gap_s: number }
export interface HistorySeries {
  days: HistoryDay[];
  oldestRecorded: string | null;   // from the response; may predate the zone (spec §4.1)
  totalL: number;
}
export class WaterHistoryCache {
  /** Returns the cached series, or null while a fetch is in flight or after a failure. */
  get(zoneId: string, days: number): HistorySeries | null;
  /** Fetches if the key changed or the entry is older than `maxAgeMs`. Safe to call from `updated()`. */
  request(hass: HomeAssistant, zoneId: string, days: number, now: number): void;
}
```

- [ ] Tests first, with a fake `hass.callService` recording calls: the request window equals the drawn window; two `request` calls with the same key produce **one** service call; a changed period refetches; a rejected call leaves `get` returning `null` and does not retry in a tight loop; the response's `zones[0].days` and `oldest_recorded` land in the series unchanged.
- [ ] Implement. `callService(DOMAIN, "get_water_history", {zone_id, start_date, end_date}, undefined, false, true)` — the `panel.ts:199` pattern. Compute `start_date` as `end - (days - 1)` in **local** days.
- [ ] `npm run test`, commit.

### Task 4: `water-chart.ts` — the SVG bar chart

**Files:** `card/src/water-chart.ts`, `card/src/water-chart.test.ts`

Spec §4.1–4.2. A Lit element taking `series`, `language`, and nothing else.

- [ ] Tests first — over the **geometry function**, not the DOM: extract `chartBars(series, width, height)` as a pure exported function returning `{x, y, w, h, est, gap, unrecorded}[]`, and test it. A day with `gap_s > 0` carries `gap: true` whatever its litres; days before `oldestRecorded` carry `unrecorded: true` and no bar; an all-zero series produces bars of zero height without dividing by zero; the tallest day fills the plot.
- [ ] Implement the element around it. Bars as `<rect>`; the estimated hatch as an SVG `<pattern>` defined once; the gap marker as a baseline tick. A legend row, rendered only for the marks actually present in the window.
- [ ] **No literal colours.** Add a test that reads the component's `styles` source and fails on `#rrggbb` / `rgb(` / named colours outside a `var(--x, fallback)` fallback position.
- [ ] `npm run test`, `npm run typecheck`, commit.

### Task 5: The four block elements

**Files:** `card/src/blocks/{next-run,programs,hardware,consumption}-block.ts` + dictionary keys

Each is a Lit element with `@property` inputs and **no service calls of its own** — actions bubble as `imc-zone-action` / a new `imc-zone-config` event, exactly as `zone-row.ts` does. The shell owns every service call. This is what keeps the blocks testable and the write paths countable.

- [ ] **`next-run-block`** (spec §3.1) — two lines, never merged. `unknown` → "non ancora valutato". Disagreeing programs → per-program list, no summary. `evaluated_at` rendered as an age.
- [ ] **`programs-block`** (spec §3, row 4) — name, start, `calendarText(...)`, enable switch, and today's **delivery** minutes from `schedule-math`'s existing helper (delivery, not setting — the contract is explicit).
- [ ] **`hardware-block`** (spec §3.3–3.4) — the three capability states; a candidate offers exactly one action, adopt, which emits an event; the meter's declared and resolved units; `battery_entity` from config when set.
- [ ] **`consumption-block`** (spec §4.4) — today/month/total from `zone_water_total`'s attributes, never summed from the series; `<imc-water-chart>` when `consumption_source: internal`; hidden entirely when `water_accounting: "unavailable"`.
- [ ] Tests per block over their pure decision helpers (which verdict line, which capability state, whether the chart is shown) rather than DOM snapshots.
- [ ] `npm run test`, `npm run typecheck`, commit.
